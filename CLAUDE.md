# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Шпаргалка для собеса (PHP/Symfony, финтех + фуллстек): ~1442 карточки вопрос-ответ по 43 темам, тёмная тема. Открывается на https://sobes.local (домен в `/etc/hosts`, TLS через общий nginx-proxy). Данные в **PostgreSQL**, отдаются тонким **PHP-API** с кэшем в **Redis**; фронт грузит всё одним запросом и ищет **в браузере** (поэтому быстро). Всё крутится в Docker.

## Команды (всё в Docker)

```bash
docker compose up -d --build                          # поднять/пересобрать стек (web, php, postgres, redis)
docker compose exec php php /var/www/api/seed.php      # (пере)залить БД из public/data/parts/*.json + db/*.json
docker compose down                                    # стоп (данные в volume sobes-pgdata сохраняются)
```

Проверять UI **только через расширение Chrome** (claude-in-chrome MCP), не через внутренний preview — внутренний preview не видит API/БД. Ассеты версионируются `?v=N` в `public/index.html` (бампать на всех `<link>/<script>` при правке фронта, иначе браузер отдаст старьё из кеша).

## Данные и бэкенд

- **Postgres** (`sobes-postgres`, БД/юзер/пароль `sobes`): `db/schema.sql` — таблицы `categories`, `questions` (q/a/detail/code/tags/weight/pinned/edited/orig/sort_order), `settings` (личные заготовки: self/task/jobs/ask), `sources` (источники мониторинга вакансий: kind `tg`|`account`, title, value [имя файла для tg / URL для account], login, password [для account, локально plaintext], enabled, `auto_apply` [авто-отклик без подтверждения для этого источника], `last_msg_id` [id последнего проанализированного тг-сообщения]), `vacancies` (найденные релевантные вакансии, score выше порога — тг-автопрогон >50, /scan_all >70: source_id, chat, msg_id, score, title, reason, link, text, `link_text` [полное описание вакансии, вытянутое по ссылке через WebFetch], `mismatches` [JSONB-массив главных несоответствий резюме], + автоотклик: `apply_status` [new|queued|approved|applied|needs_manual|skipped], `applied_at`, `cover_letter`, `apply_note`; + компания: `company` [название работодателя], `company_url` [найденный сайт/раздел вакансий вне источника]), `notifications` (под колокольчик: vacancy_id, kind, title, body, read — создаётся при `needs_manual`), `agent_log` (лог работы автопрогона: kind, message, meta, created_at — видно на странице «Лог агента»). Источник правды.
- **Сид**: `api/seed.php` (запуск в php-контейнере) читает `db/categories.json` (порядок+названия), `public/data/parts/<key>.json` (карточки с полем `weight`), `db/personal.json`. **`TRUNCATE questions` — перезаливаются ТОЛЬКО вопросы**; категории и personal вставляются `ON CONFLICT DO NOTHING`, т.е. их правки в БД НЕ затираются пересидом (файлы `db/*.json` — только первичный бутстрап). `orig` = снимок карточки для «вернуть оригинал». Если правил `db/personal.json` и надо ФОРС-залить в БД (перезаписать) — `docker compose exec php php /var/www/api/refresh_personal.php` (вопросы/закрепы не трогает). **Добавить НОВЫЕ карточки без пересида** (полный `seed.php` снёс бы правки/закрепы через TRUNCATE) — дописать в `parts/*.json` и `docker compose exec php php /var/www/api/seed_append.php`: вставляет только отсутствующие `(category_key, q)`, существующие строки/закрепы не трогает.
- **Redis** (`sobes-redis`): кэширует собранный JSON под ключом `sobes:cards`; любая правка делает `DEL` (см. `cacheBust()`).
- **API** `api/index.php` (php-fpm, PDO+phpredis, без фреймворка). Роуты после `/api`:
  - `GET /cards` — `{categories, items, personal}` из кэша (на промахе собирает из БД и кэширует).
  - `POST /cards/{id}/pin {pinned}` · `POST /pins/clear` — закрепы.
  - `PATCH /cards/{id}` (q/a/detail/code) → `edited=true` · `POST /cards/{id}/reset` → восстановить из `orig`.
  - `PATCH /personal/{self|task|jobs|ask}` {title, body} — правка личных заготовок.
  - `GET /tg-files` — список файлов выгрузки из `.claude/tg_history` (папка примонтирована в php как `/var/www/tg_history:ro`).
  - `GET /sources` (пароль НЕ отдаёт, только `login`+`hasPassword`+`autoApply`) · `POST /sources {kind,title,value,login?,password?}` (уникальность по `(kind,value)`, дубль → `{ok:true,existed:true}`) · `PATCH /sources/{id} {enabled?,auto_apply?}` · `DELETE /sources/{id}`.
  - `GET /vacancies` (отдаёт `sourceId` + `chat` [имя источника, метка чипа фильтра] + `kind` источника + apply-поля) · `DELETE /vacancies/{id}` — найденные вакансии · `POST /analyze/request` · `GET /analyze/status`.
  - `GET /log` — последние записи лога агента (новые сверху) · `POST /log {message, kind?, meta?}` — добавить запись. Агент из bash пишет через CLI `api/log.php` (stdin JSON), фронт читает `GET /log` на странице «Лог агента».
  - Автоотклик: `PATCH /vacancies/{id}/apply {apply_status?,cover_letter?,apply_note?}` (ставит агент; `needs_manual` создаёт уведомление; `applied` проставляет `applied_at`) · `POST /vacancies/{id}/approve` (юзер одобряет: queued/needs_manual→approved) · `POST /vacancies/{id}/skip` · `PATCH /vacancies/{id}/company {company?,company_url?}` (сохранить найденный сайт компании) · `POST /applied/check` (флаг сверки откликов; кнопки «✅ Обновить» и «🔄 Прогнать сейчас» из UI убраны, роуты `/applied/check` и `/analyze/request` оставлены как флаг-механика). Уведомления: `GET /notifications` (+unread) · `POST /notifications/read {id?}` (без id — все).

**Анализ вакансий (AI-матчинг):** `api/scan_tg.php` выдаёт новые тг-сообщения (id > last_msg_id) → Claude по каждому тянет полное описание вакансии по ссылке из поста (WebFetch, т.к. в тг-посте обычно только заголовок) и оценивает на соответствие резюме (`db/personal.json` / `[[user-resume-profile]]`) с учётом требуемого английского относительно B1 кандидата, оставляет score>70, выписывает `mismatches` (главные несоответствия) → `api/save_results.php` (stdin JSON `{matches, last}`; поля matches: source_id/chat/msg_id/score/title/reason/link/text/link_text/mismatches) пишет `vacancies` + двигает `last_msg_id` + снимает флаг. Промпт скоринга — `scripts/monitor_prompt.txt`. Ручной/сессионный прогон: скан → воркфлоу (по агенту на чат, каждый фетчит ссылки и скорит) → save. Фронт: карточка показывает score/title/reason, блок «⚠ Несоответствия», ссылку «открыть» и тоггл «Текст сообщения» (пост в тг + описание по ссылке). **Автопрогон тг — локальная плановая задача (БЕЗ API-ключа).** Планировщик Claude Desktop `sobes-monitor-tick` (`~/.claude/scheduled-tasks/`, крон `7 * * * *` — раз в час, пока ноут включён и Claude Desktop открыт; если приложение было закрыто — выполнится при следующем запуске) на каждом прогоне читает playbook `scripts/agent_run.md` и делает всю работу САМ, своей головой (внешний ключ не нужен — скорит сам агент в сессии): старт-лог → `scan_tg.php` (новые сообщения) → скоринг каждого под резюме по `monitor_prompt.txt`, но с **порогом 50** (не 70) → релевантные (score>50) через `save_results.php` в «Новые» → лог на каждом шаге через `api/log.php` (видно на странице «Лог агента», #log). Прежний launchd-крон (`monitor_run.sh` + `ANTHROPIC_API_KEY`) больше НЕ используется — headless Claude в фоне/кроне даёт 401; `monitor_run.sh`/`com.sobes.monitor.plist` лежат в `scripts/` как история. **Сайты — Фаза B playbook, УСЛОВНО:** агент пытается сканить привязанные account-источники (hh.ru=13, Хабр=15) на КАЖДОМ прогоне, но только если доступен живой залогиненный браузер (Chrome-расширение). В чисто фоновом тике браузера обычно нет → Фаза B логируется как пропущенная (не падает); капча/2FA на сайте → сайт пропускается. Полноценно сайты идут, когда агент в живой сессии / «Run now» при открытом залогиненном Chrome. Флоу B: поиск за неделю (hh `search_period=7&schedule=remote&order_by=publication_time`, Хабр `remote=true&sort=date`) → отсев «Вы откликнулись» и уже сущих `(source_id,msg_id)` → скоринг>50 → `save_results.php` с `last:{}` (дедуп по ключу). Тг-источники: Remote IT (11), Gamedev (14), WEB3 (16), hh-бот "Работа и вакансии на hh.ru" (17 — тоже вакансии с hh.ru).

**Дедуп выдачи:** `GET /vacancies` схлопывает вакансии по нормализованному заголовку (одна и та же вакансия с hh-сайта и из тг-канала hh-бота = дубль). На группу оставляет богатейшую строку: `applied` > `needs_manual` > с полным описанием (`link_text`) > выше score. В БД строки не трогаются, дедуп только на отдаче.

**Скан сайтов (`kind='account'`, hh.ru/Хабр) — команда `/scan_all`:** только в живой сессии с залогиненным браузером (Chrome-расширение). Headless/крон для сайтов НЕдоступен: расширение (интерактивная авторизация) в фоне не поднимается + на входе бывает капча (Хабр — Yandex SmartCaptcha; капчи не проходим). Флоу: логин-чек (пароль подставляет менеджер паролей юзера, сам не ввожу) → поиск за неделю (hh `search_period=7&schedule=remote`, Хабр `remote=true&sort=date`) → шортлист по заголовку → отсеять уже применённые ("Вы откликнулись") и уже сущие `(source_id,msg_id)` → скоринг-воркфлоу (агент на вакансию, WebFetch+оценка, `msg_id`=числовой id из URL) → `save_results.php`. Ежечасно — `/loop 1h /scan_all` в открытой сессии.

**Автоотклик — команда `/apply_vacancies` (запускать по запросу):** режим зависит от флага источника `sources.auto_apply`. **auto_apply=false (по умолчанию):** безопасная схема **черновик→одобрение в UI→отправка**. Фаза 1: по `new` открыть вакансию, написать сопроводительное → `queued`; если внешняя форма/тест не по зубам → `needs_manual` (+уведомление). Фаза 2: по `approved` (юзер нажал «Одобрить отправку») — откликнуться, вставить письмо, отправить → `applied`. **auto_apply=true (галочка «🤖 авто» на источнике):** по `new` из этого источника отклик СРАЗУ без подтверждения (сопроводительное + отправка → `applied`); флаг — стоячее разрешение юзера. Работодателю в ручном режиме ничего не уходит без `approved`. Фронт мониторинга: над списком — строка фильтра по источникам (чипы `#vac-stats` `.vac-src` = имя чата источника + счётчик; «Все» + по одному на каждый присутствующий в выдаче источник; счётчик в рамках выбранного статуса, пустые под текущим статусом скрыты, кроме «Все»; ключ фильтра — `sourceId` из ответа `/vacancies`; комбинируется со статус-фильтром сайдбара), бейдж статуса на карточке (🌐 у сайтовых), блок черновика с кнопками «Одобрить/Пропустить», тумблер «🤖 авто/вручную» на каждом источнике, колокольчик со счётчиком. Кнопка «🔎 искать компанию» на карточке: если есть `company_url` — прямая ссылка на сайт/вакансии компании («🏢 сайт компании»), иначе веб-поиск careers-страницы вне источника. `company_url` резолвится сессионным воркфлоу (WebSearch по названию компании → официальный сайт/раздел вакансий). В левом меню мониторинга — фильтры по статусу (Новые/Откликнулся/Нужна форма/Пропущенные, пустые скрыты). Флаг `applied_check_requested` (кнопку «✅ Обновить» из UI убрали; флаг ставится роутом `/applied/check`) → команда **`/refresh_applied`** (в сессии): открывает «Мои отклики» на hh (`/applicant/negotiations`) и Хабре (`/responses`), собирает id откликов, сверяет с `msg_id` вакансий (source 13/15) и помечает совпавшие `applied` — они уходят в фильтр «Откликнулся». НЕ 88 заходов, а 1-2 страницы списка.
  - `PATCH /categories/{key}` {title} — переименование · `POST /categories/reorder` {order:[key]} — порядок (правило reorder ДО правила `{key}`, иначе "reorder" матчится как ключ).
  - Redis необязателен: при недоступности код падает на прямой запрос к БД.

В UI редактируются вопросы (карандаш) и personal (карандаш в попапе) — канонично в БД. Категории в UI НЕ редактируются (по просьбе пользователя кнопку убрали); их правит только бэкенд-API (`PATCH /categories/{key}`, `POST /categories/reorder`) — вызывать по запросу. Массово вопросы — правишь `parts/*.json` → `seed.php` (категории/personal при этом сохраняются).

## Фронт (`public/`, без сборки, неймспейс `window.SOBES`)

Порядок в `index.html`: `api.js` → `search.js` → `app.js`. `app.js` при старте делает `SOBES.api.load()` (`GET /api/cards`), кладёт в `SOBES._items`, `window.PERSONAL`, строит сайдбар и рендерит.

- **`api.js`** (`SOBES.api`): fetch-клиент — `load`, `setPin`, `clearPins`, `saveEdit`, `reset`. Правки/закрепы **оптимистичны**: UI меняется сразу, запрос в фоне, при ошибке — откат + alert. Флаги `pinned`/`edited` приходят прямо в item из БД (никакого localStorage).
- **`search.js`** (`SOBES.search`): движок в браузере. `reindex(it)` строит `_hay/_hayLat(транслит)/_tokens/_q/_a/_detail/...`. Поиск — AND по термам с весами полей; варианты терма: основа (стемминг рус), смена раскладки RU↔EN, транслит; пустой результат → fuzzy по Левенштейну. Сортировка: закреплённые → (в поиске: релевантность + подмешанный `weight`·0.03) → `weight` desc → индекс. **После правки текста карточки звать `engine.reindex(it)`**.
- **`app.js`**: весь UI (один IIFE). Рендер **чанками** (`CHUNK=70`, первый синхронно — быстрый первый экран); подсветка кода **ленивая** (`ensureHl` при раскрытии «Подробнее»); мини-markdown (`mdInline/mdBlock`) и мини-подсветка (`highlightCode`+`KW`) без либ; подсветка совпадений через `TreeWalker`. Главная без категории/поиска = только закреплённые (поиск при этом по всем). Одна кнопка «📋 Текущая вакансия» (`#openVacancy`) → попап `openVacancy()` со ВСЕМИ 4 личными блоками (self/task/jobs/ask из `window.PERSONAL`) секциями `.psec`, у каждой свой карандаш → `editPersonalSection()` (правит одну секцию, `PATCH /personal/{key}`, возврат в попап). Мониторинг вакансий — ОТДЕЛЬНАЯ страница (роут `#monitoring`); Лог агента — ещё одна (роут `#log`, ссылка «📜 Лог агента» в сайдбаре мониторинга `#sidebar-log`, «← К мониторингу» назад). В `#main` три view (`#cheatsheet-view`/`#monitoring-view`/`#log-view`), `route()` по hashchange; клик по категории/Esc → назад. Суфлёр — НЕ страница, а РЕЖИМ на главной (тумблер `#suff-toggle` в топбаре): при включении (`suffMain`) `render()` при пустом поиске делегирует в `suffShow()` — подсказки рисуются прямо в `#results` вместо закреплённых; уход в мониторинг глушит суфлёр (`suffStop()`).

**Суфлёр (live-ответы, тумблер «🎧 Суфлёр» `#suff-toggle` в топбаре главной — НЕ отдельная страница):** во время созвона ловит голос собеседника и сразу подкидывает ответы из базы карточек. Весь код — в IIFE `app.js` (переиспользует `makeCard`/`openDetail`/`escHtml`), панель `#suff-bar` (статус + ручной ввод `#suff-manual` + транскрипт) в `index.html` под топбаром, стили `.suff-*`. Включение (`suffEnter`) → `suffMain=true`, `suffShow()` рисует подсказки в главный `#results` вместо закреплённых, затем `suffCapture()` (живой звук; если отменён/недоступен — режим остаётся, работает ручной ввод). Флоу захвата: `getDisplayMedia({video:true,audio:true})` (юзер шарит вкладку со звонком + галка «звук вкладки»; берётся ВЫВОД вкладки = только собеседник, свой микрофон не пишется, видео-трек глушим) → Web Speech `SpeechRecognition` (`ru-RU`, continuous+interim, поток подаётся через `rec.start(audioTrack)` — **нужен Chrome 135+**, авто-рестарт по `onend`) → распознанная фраза в `suffPick()`: НЕ строгий AND, а keyword-overlap + словарь концептов `SUFF_CONCEPTS` (~75 групп: любая форма термина — «ооп»/«oop»/«объектно-ориентированное»/на слух — бустит нужную категорию и добавляет чистые термины; решает проблему «как бы Web Speech ни сказал»). Бьёт фразу на смысловые слова (минус `SUFF_STOP`, короткие аббревиатуры типа «бд» проходят), гоняет каждое через `engine.run(word)`, ранжирует по (слово-совпадения + буст категории·1.5), дедуп по тексту вопроса, топ-4, верхняя авто-раскрыта. Поле ручного ввода `#suff-manual` (Enter) — фолбэк/тест без звонка. Текущий STT = бесплатный Web Speech (русский уходит на сервера Google, длинный стрим сам рвётся — держится на авто-рестарте). Апгрейд (не сделан): стриминговый STT Soniox/Deepgram через AudioWorklet→PCM→WS с ключом в PHP-прокси, либо локальный whisper.cpp; для нативных звонилок (не браузер) — захват через BlackHole. Подробности и ресёрч — память `[[suffler-live-answers]]`.

## Отдача (docker)

`docker-compose.yml`: `web` (nginx:alpine) монтирует `public/` ro и `docker/site.conf`, в сетях `proxy-network` (внешняя, общий reverse-proxy) + `sobes-internal`; роут `/api/` → `sobes-php:9000` (fastcgi). `php` (`docker/php/Dockerfile`: php-fpm-alpine + pdo_pgsql + redis + opcache) в `sobes-internal`, монтирует `api/`, `db/`, `public/`, `.claude/tg_history/` (ro). Домен `sobes.local` — в общем nginx-proxy (см. память `local-domain-recipe`), сертификат mkcert.
